# ui-flow: 動線ファーストUI設計

## 発動条件

UI / LP / 管理画面 / Chrome拡張の画面 / HTMLツールの新規作成・大幅改修。
適用は自動。**利用シナリオはユーザーに聞かず文脈から推定し、承認待ちもしない。**

## 手順

1. **実装前に動線設計**(内部作業、ユーザーに見せるのは完成後):
   - この画面で「やりたいこと」を列挙し、頻度順に並べる
   - 各タスクの到達ステップ数を数える(主要タスクは3クリック以内に収める)
   - 画面が2つ以上あるなら遷移図を先に描いてから実装に入る
2. **実装**(下記ルール準拠)
3. **納品報告**に動線の説明を添える(画面2つ以上なら mermaid 遷移図、1画面なら一言でよい)。スクショ検証は行わない

## 動線ルール

- 1画面につき主アクション(一番目立つボタン)は1つ
- 主要タスクは3クリック以内で完了
- 常に「戻る / やり直す」手段がある。行き止まり画面を作らない
- 現在地がわかる(タイトル・パンくず・ステップ表示のいずれか)
- 破壊的操作(削除・送信・課金)だけは確認を挟む。それ以外に確認ダイアログを足さない
- 入力フォームは必須項目を最小限に。エラーはその場で、該当項目の隣に赤字表示
- 要素は使う頻度順に上から / 左から。低頻度機能は畳む(アコーディオン・詳細設定)

## 見た目ルール

- 余白: 8px の倍数のみ (8 / 16 / 24 / 32 ...)
- フォント: 2種まで。本文 16px 以上、行間 1.5 以上
- 色: 背景 + 文字 + アクセント1色の3色構成。文字コントラスト比 4.5:1 以上
- 行長: 全角40字以内で折り返す
- ボタンは押せる見た目(色付き・角丸・ホバー変化)、クリック領域 44px 以上
- 装飾(グラデーション・影・アニメーション)はデフォルトで使わない。頼まれた時だけ

## 納品前セルフチェック(机上のみ、スクショ不要)

- [ ] 初見で5秒以内に「何をする画面か」わかるか
- [ ] 一番やりたい操作が一番目立っているか
- [ ] 行き止まり(戻れない画面・閉じられないモーダル)がないか
- [ ] 動線ルール・見た目ルールの数値違反がないか
